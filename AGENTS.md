# Dotfiles Conventions

- Four files, split by kind and by shell, not by which shell the request names: environment variables go in .bash_profile, aliases and functions in .bashrc, and .zprofile/.zshrc hold only what cannot work in bash (they source their bash counterpart first). A request to "add this to ~/.zshrc" is about where the user happens to keep their own config — route it by kind, so an `export` lands in .bash_profile and both shells get it
- Keep aliases and functions in SEPARATE sections in .bashrc — never define functions inside the alias block
- Prefer separate named shortcuts (e.g. lst10/lst20/...) over a single parameterized function, but have them delegate to a shared helper (e.g. `_lst`)
- zsh does NOT word-split unquoted variable expansions like bash does. To split a string into words, use `${=var}` in zsh (or build an array). Store multi-word commands in an array and invoke with `"${arr[@]}"` so they work in both bash and zsh
- `npm run lint` shellchecks the bash files (.bash_profile, .bashrc, scripts/*.sh) and runs `zsh -n` on the zsh files (.zshrc, .zprofile). Never run shellcheck on a zsh file — it has no zsh dialect, so forcing `-s bash` flags correct zsh (`$arr[i]`, `${(f)...}`, `${=var}`, `echo` escapes) as errors
- Declare function variables with `local` in both bash and zsh — an undeclared assignment inside a zsh function leaks into the interactive shell. `setopt warn_create_global` reports these at runtime. Declare the names on one `local` line at the top of the function and leave the assignments bare, so command substitutions do not trip SC2155. Loop variables count too, except single-letter indices (`i`, `j`), which are conventional throwaways and are left alone
- The shell that runs agent commands sources this repo, so its aliases and functions shadow system commands: `dd` is the dotfiles diff (not `/bin/dd`) and `grep` is `--color=always`, which puts escape codes into piped output. In commands and scripts, call `command dd`, `/bin/dd`, `/usr/bin/grep`, or pass `--color=never`
- Never edit the main checkout (`/Users/raine/projects/dotfiles`) or `~/.zshrc`, `~/.bashrc`, `~/.bash_profile`, `~/.zprofile` and the other dotfiles, which are symlinks into it: every new shell reads that working tree, and an edit left uncommitted there blocks other sessions' landings. Develop in `.claude/worktrees/`, demo under the lock with the `test` skill (`scripts/dotfiles-test-lock.sh`, which snapshots and restores the live files), and land with `ship`. Only then claim a change is live, and check with a fresh login shell (`zsh -lic 'echo "$VAR"'`) — the agent shell does not load .bash_profile, so its environment says nothing about the exports. Details in `docs/workflow.md`
- Some tools apply their own defaults only while an env var is unset, so exporting it drops them: git sets `LESS=FRX` for its pager only when `LESS` is unset, and `LESS='-i'` alone left git printing raw `ESC[` codes. Before exporting a shared var (`LESS`, `PAGER`, `GREP_OPTIONS`), carry over the defaults it displaces and comment why they are there
- Compiled helpers live in `bin/*.swift`. The function that uses one compiles it into `~/.cache/dotfiles/` on first use and rebuilds when the source is newer, so nothing built is checked in and no manual build step exists. `docs/` holds the findings behind non-obvious helpers; read the matching doc before reworking one (e.g. `docs/macos-text-replacements.md` for `bin/ksreplace.swift`)
- The main checkout is shared, so it can hold another session's uncommitted edits or demo copies. `ship` checks it before landing anything and commits leftovers that are already live (step 0); never commit while another session holds the demo lock, and never check edits out of the live files
- To find that session, run `search_session_transcripts` (with `include_archived`) on a distinctive identifier from the diff, such as a function name, then read its tail with `list_events`. A generic string like an env var name matches unrelated sessions. `stat` on the file dates the edit
- The repo is public on GitHub (`raineorshine/dotfiles`). Read every diff for secrets before pushing, including another session's edits
